# Plan: Implementar Códigos de Barras en Tickets de Precios

## Contexto y Objetivo
El usuario confirmó que quiere rellenar el gran espacio en blanco que actualmente existe en la parte inferior de cada ticket de precio.

Ese espacio fue dejado intencionalmente para un código de barras.

Los SKUs de sus productos tienen el formato típico `COC-0200304` (3-4 letras + guión + números).  
Esto es **perfecto para Code128**.

**Decisión tomada:** Usar **bwip-js + Code128** (la recomendación estándar para este caso).

## Objetivo del Plan
Agregar generación real de códigos de barras (Code128) en los tickets de precios, utilizando el campo `sku` del producto, y aprovechar el espacio vacío actual.

- **Gran espacio vacío** entre el precio y el texto inferior

## 2. Solución Técnica Recomendada

### Librería: `bwip-js`
- Excelente integración con PDFKit.
- Soporta `code128` de forma nativa.
- Puede generar PNG en memoria (Buffer) de forma asíncrona.
- Permite `includetext: true` (muestra el SKU debajo de las barras, legible por humanos).

**Parámetros recomendados para este caso:**
```ts
{
  bcid: 'code128',
  text: sku,                    // "COC-0200304"
  scale: 2.5,
  height: 10,                   // mm
  includetext: true,
  textxalign: 'center',
  textsize: 7,
  paddingtop: 2,
}
```

### Estrategia de implementación:
1. **Pre-generar** todos los códigos de barras **antes** de crear el PDF (porque `bwipjs.toBuffer` es async).
2. Cachear por SKU (muchos tickets pueden ser del mismo producto).
3. Adjuntar el `Buffer` PNG a cada ticket expandido.
4. Dibujar con `doc.image(buffer, x, y, { width, height })` en la zona vacía.
5. Ajustar las posiciones verticales del ticket para que quede equilibrado.

### Paso 2: Modificar `generatePriceTicketsPdf` (catalog.service.ts)

#### 2.1 Después de construir `expandedTickets`, generar los barcodes:

```ts
// Cache de barcodes por SKU
const barcodeCache = new Map<string, Buffer>();

const ticketsWithBarcode = await Promise.all(
  expandedTickets.map(async (t) => {
    if (!t.sku) {
      return { ...t, barcodePng: null };
    }

    if (barcodeCache.has(t.sku)) {
      return { ...t, barcodePng: barcodeCache.get(t.sku)! };
    }

    try {
      const png = await bwipjs.toBuffer({
        bcid: 'code128',
        text: t.sku,
        scale: 2.5,
        height: 9,
        includetext: true,
        textxalign: 'center',
        textsize: 7,
      });
      barcodeCache.set(t.sku, png);
      return { ...t, barcodePng: png };
    } catch (err) {
      this.logger.warn(`No se pudo generar código de barras para SKU: ${t.sku}`);
      return { ...t, barcodePng: null };
    }
  })
);
```

#### 2.2 Rediseñar el layout del ticket (dentro del bucle de dibujo)

Nuevo orden propuesto (de arriba hacia abajo):

1. Nombre del producto (bold, 2 líneas máx.)
2. Precio grande (centrado)
3. **Código de barras** (centrado, ~28-32mm de alto)
4. Categoría (muy pequeño, opcional, justo encima o debajo del barcode)

Ajustes sugeridos de posiciones:
- Name: `y + 6`
- Price: `y + 32`
- Barcode image: centrado verticalmente en la zona `y + 55` a `y + ticketHeight - 22`
- Category (si existe): justo encima del barcode o integrado en el texto del barcode (bwip-js ya incluye el SKU legible).

#### 2.3 Dibujar el código de barras:

```ts
if (t.barcodePng) {
  const barcodeWidth = contentWidth * 0.85;
  const barcodeHeight = 32; // puntos
  const bx = contentX + (contentWidth - barcodeWidth) / 2;
  const by = y + 58;

  doc.image(t.barcodePng, bx, by, {
    width: barcodeWidth,
    height: barcodeHeight,
  });
}
```

### Paso 3: Actualizar el frontend (mínimo)

No se requieren cambios grandes en `PriceTicketsPage.tsx`.

### Paso 4: Ajustes de espaciado y calidad visual

- Revisar `ticketHeight` y márgenes si es necesario.
- Probar con SKUs largos (ej. "COC-0200304").
- Asegurar que el código de barras no se salga del ticket.
- Considerar reducir un poco el tamaño de la fuente del nombre si hace falta más espacio para el barcode.

### Paso 5: Manejo de casos edge

- Producto sin `sku` → no dibujar código de barras (o usar el `id` del producto como fallback).
- Error al generar barcode → log + continuar sin código (no romper la generación del PDF).

## 5. Riesgos y Consideraciones

- **Rendimiento**: Generar 100-200 códigos de barras por PDF es rápido con bwip-js (milisegundos por código). Cache por SKU evita trabajo duplicado.
- **Tamaño del PDF**: Los PNG de bwip-js son pequeños.
- **Escaneo**: Code128 con estos parámetros se escanea muy bien en impresoras normales.
- **Compatibilidad**: Funciona en el mismo entorno actual (Nest + pdfkit).
